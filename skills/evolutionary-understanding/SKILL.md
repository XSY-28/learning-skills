# 演化式理解

从基本对象、原始问题和当时约束出发，重建关键变化怎样形成当前结构。帮助学习者解释机制为何存在、代价是什么、条件变化后哪里可能需要调整。历史负责约束事实，概念依赖负责安排教学顺序。

## 确定本次入口

- 从当前请求确定对象、学习目标、已有基础、材料和篇幅。信息足以开始时直接推进；只澄清会显著改变结果的歧义。默认中文、对话交付，不自动创建学习档案或修改项目。
- 用一个具体任务或问题说明本次要理解什么，再给当前对象的最小地图。大项目可以先选一条关键执行路径；领域入门先识别主要问题和分支，不把某个项目的路线当作整个领域的历史。
- 选取与目标有关的简单起点，不必追到最早起源。教学上最容易的起点，不一定是历史上第一个版本。
- 该方法组织“为什么变成这样”。已有讲解或辅导约定继续有效，不另叠加一套问卷、模式、总结和测验。显式调用也服从用户的局部问题、长度和“不出题”等要求。

## 选择材料与讲解路线

不要求用户先选模式；按问题和证据选择，必要时混合：

| 路线 | 适合什么情况 | 必须保留的边界 |
| --- | --- | --- |
| 真实历史追踪 | 有可读版本、讨论、原始论文或档案，需要解释实际变化 | 只把来源支持的事件与动机当作史实；时间先后本身不证明因果。 |
| 教学性重建 | 历史零散，或需要更短的概念依赖路径 | 明说“下面是教学重建，并非真实发明史”；可调整顺序，不虚构日期、人物、提交或引文。 |
| 从现状反向追问 | 已知某机制，想理解它为什么存在 | 用“去掉它会怎样、什么条件下才需要它”提出解释，再核查历史；功能合理不证明实际来历。 |

用户明确要真实历史而资料不足时，指出缺失的哪一段、已查材料及对结论的影响，继续讲证据充分的部分；教学替代内容单独标明，不能冒充已完成真实历史调查。

为关键主张选取相称的原始材料：代码与版本、同期讨论和设计文档、论文、实验记录或档案。当前行为、性能和最新结论需要对应版本或证据；年代名称和作者记忆都不能代替核实。软件项目读取 [软件历史取证](references/software-history.md)，其他场景不必加载。

## 重建有解释力的转折

以理解价值筛选转折：它是否改变了问题、关键约束、基本假设、核心结构、适用范围或重要取舍？连续的小变化可以合并成一个转折；同一大改动也可能包含几个不同决定。保留真正影响解释的分支、失败、回退和长期共存，不默认“大部分都是小改动”适用于所有对象。

阶段与章节标题直接概括关键修改，使用简短、陈述性的短语，例如“引入会话持久化”“工具接口与执行实现分离”。标题不用问句、设问式引导或教人做事的口吻，不写“先回到……”“怎样才能……”等叙事铺垫；日期按需附加。

对选中的转折，沿下面的推理链展开，正文自然连接，不必逐项填表：

> 当时要解决什么 → 简单/旧方案在什么条件下不够用（或为何改变目标）→ 有哪些当时可行的选择 → 实际变化是什么、选择依据是什么 → 得到了什么、付出了什么 → 对今天留下了什么影响。

- 用一个可跟随的例子展示旧方案的具体限制，再引入新机制。沿同一案例逐层推进，避免一次加入几个尚未解释的抽象。
- 重要分叉比较实质不同的方案；只有一个方案有记录时，其他可能方案标为分析中的反事实，不能称为当时真实讨论过。判断是否可行，要考虑当时可用的知识、资源与技术。
- 分开判断：当时合理、今天必要、普遍最优。兼容成本、组织利益、偶然事件与失误都可能塑造结果；只在有证据时归因，不把每次变化解释成必然进步或最优解。
- 关键处区分“来源直接支持”“根据材料推断”“教学假设”。当事人陈述说明其报告的理由，效果仍需证据；声称性能提高不等于已测得提高。来源冲突时呈现冲突及影响，不为故事顺畅抹平分歧。

一个教学重建例子：顺序任务遇到重启丢进度 → 保存任务记录；多个工作进程争抢 → 增加领取规则；外部操作成功但完成记录未写入 → 恢复仍可能重复操作。每层解决不同问题，不能把“能恢复”推成“外部效果恰好一次”。这是理解机制的例子，不是任何真实项目的历史。

## 跨领域保持证据标准

工程与制度可讨论设计选择，但需区分参与者的不同目标；一个群体受益不代表整体更优。理论与科学领域关注问题、假设、可解释现象和证据的变化，保留并行路线与适用区间，不能用历史故事代替证明或实验。自然演化与非意图过程使用机制、条件和证据解释，不拟人化成主体为某个目标作出设计决定。

类比用于帮助进入问题时，说明对应关系及失效处；对象没有有用的演化链，或当前障碍是定义、推导、操作时，直接补该缺口，不为套用方法编造发展阶段。

## 回到现在并检查理解

- 把选中的转折映射回当前结构或概念关系，沿一次真实任务/现象解释各部分如何共同工作。检查机制之间的相互作用；局部改动连贯，不代表组合后没有新复杂性。
- 指出仍有效的约束、可能只因兼容而保留的部分、当前争议和未知。只在有支持时给结论；说明什么证据会改变重要判断。用户要快速入门时，优先讲解释主线，旁支按需深入，不无限穷举历史。
- 若适合当前学习约定，用一个删除机制、改变约束、比较分支或迁移应用的小问题检查理解；给用户作答空间，不在同一轮替答。只认可回答实际展示的能力；没有回答就不宣称掌握。纯交付或用户拒绝练习时不加题。
- 交付前核对：是否解释了变化理由而不只是列事件；是否混淆史实与重建；是否把后出现当作更优；能否连接当前结构与边界；关键来源是否可定位。按需用简短转折表或带分叉的图辅助，不固定栏目数量。

一次讲解完成不等于学习有效，更不证明“更快”。提速或掌握程度需要相应的学习者表现与比较证据，不从回答流畅、材料齐全或代理试跑通过推断。
