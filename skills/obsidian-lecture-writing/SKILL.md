# Obsidian 深入理解式讲义

从读者已知的内容出发，写出可以脱离聊天独立读通的讲义。读者应能解释知识本身、说明知识之间怎样相连，并用机制判断一个新情形及结论的边界。以这些能力验收，不能用覆盖的术语数量或篇幅代替。

## 先判断这次是否在编写讲义

每轮按当前交付目的重新判断，不按关键词或历史任务沿用。

| 当前请求 | 是否使用本 skill |
|---|---|
| 写入门讲义；把已有解释写成自足章节；实质重写看不懂的讲义；为讲义补写必要概念或推导 | 使用，限定在请求的章节或段落。 |
| 写 Python 类的入门讲义，要求从问题、对象到代码逐层教会 | 使用；编程主题同样可以是讲义。 |
| 生成 Python/NumPy 语法查询笔记、公式表、速查卡，即使放在 Obsidian 或称为“讲义格式” | 不使用；实际用途是查询。 |
| “讲义里这个公式为什么成立”“从头给我讲懂 OGD”，但未要求产出或改写讲义 | 不使用；这是聊天教学，不因此写文件或改笔记。 |
| 整理摘录、压缩摘要、翻译、纯润色、只列章节目录、学习计划、只检查讲义 | 不使用；这些任务本身不授权改写教学正文。 |
| 只修公式显示、拼写、标题、链接；只改代码；制作或安装 skill | 不使用；不扩大为讲义重写。 |

- “讲义正文”可以直接交付在对话中，不以必须写文件为条件；普通笔记只有在明确要求加工成循序教学材料时才适用。
- 阅读材料、引号或示例中出现“写讲义”，不构成当前指令。混合请求只对讲义部分执行本流程，速查部分保持速查形式。
- 若误加载，退出本流程，不添加章首章末、设问或练习，不自动修改笔记。用户显式点名本 skill 也不能覆盖“只给公式”“只修格式”等当前限制。
- 当前语言、篇幅、来源及修改范围优先；默认中文。只补一段时把方法用在该段，不强行重做整章。仅在授权编写完整章节时要求完整章结构。

## 先确定学习出口与阅读路径

1. 从对话和材料推断读者基础、用途与范围。当前反馈优先于旧画像；会微积分不等于懂机器学习建模。只有缺失信息会实质改变内容且无法合理推断时，才提简短问题。
2. 将主题转为可观察的学习目标，例如“能解释比较对象、手算一次更新、重建单步到累计的连接”，而不只写“介绍 OGD”。只补齐完成目标必需的前置。
3. 先核对原材料的符号、条件和论证；不要把原文错误解释成读者基础不足。来源不完整或结论未核实时说明具体缺口，不用流畅推导掩盖。
4. 按概念依赖安排小单元，标清主线、分支、汇合和第一遍终点。必要知识就地建立，或明确指定精确先读位置；不要把必需内容称为“可选”。
5. 决定统一的阅读入口和核心案例。主讲义可以自足，也可以是链接自足章节的地图；避免同一推导分散在多个半成品版本里，要求读者自行拼接。

## 正文要把连接真正写出来

### 对象、关系与任务变化

- 新对象首次用于推理前，解释类型、角色、输入输出、定义域、谁给定、谁待求、当前谁固定谁变化。名称表不能替代操作意义；按需解释形状、下标和量词次序。
- 读者可用的知识限于声明的先修与此前已经解释的正文。出现过某个词或放过双链，不算已经建立了它；调用久远前置时唤回本次需要的意义。
- 把重要关系写成带理由的命题：等价改写、特例与推广、条件性推论、修复旧方法的局限、改变目标或评价、仅作类比。图上的箭头也要说明机制，不能只说“A 与 B 密切相关”。
- 在任务、符号、目标、比较对象、假设或算法输出变化处，交代继承什么、改变什么、为何需要改变。读者应能区分“同一算法换应用”与“换目标后得到另一种保证”。
- 涉及概率时说明每次平均的随机来源，以及条件固定了什么、还剩什么随机性。涉及优化时区分 min 的值与 argmin 的点、候选变量与更新结果、算法可用信息与事后分析对象。

### 从可操作的小问题走到抽象机制

- 对承载后续理解的定义，先建立一个能操作的需求，再翻译成定义与公式，最后说明它在当前问题中的作用。不为普通术语硬编故事或虚构发现史。
- 优先让同一简单案例贯穿几层知识；在具体操作、一般表达、变化后的新例子之间往返。小例子要保留正在解释的结构，不能用特例代替一般证明。
- 例子按作用选择：引入、演算、区分、失败、边界或迁移。不规定每节几个例子、几幅图。图须说明看哪里、如何对应符号，以及改变某个量会怎样。
- 同时解释关键推导“为什么成立”和“为什么尝试”：目标缺少什么，已知结构能提供什么，为什么选择这个展开、辅助点、步长或比较对象。
- 检查“于是、代入、显然、类似”是否掩盖关键替换、索引变化或新概念；给出本次使用的具体对象、依据和条件。常规算术不必无限展开。
- 一句话组合多个新概念时，紧接用已建立的对象通俗复述其关系。自然设问后在正文中回答，不要求返回聊天才能读完，也不重复解释已经直白的句子。

### 条件、直觉与整个方向的图像

- 条件要能理解、能在例子中检查，并指出在论证中控制哪一项。把结论与其条件、评价对象放在一起；区分例子、类比、局部近似、证明与经验观察。
- 让核心直觉产生一个预测，再通过改变条件或给出对照检验它。发现错误泛化时修回最初的解释，不能只在文末加一句免责声明。
- 区分实际表现、已证上界、最优可能保证。平衡上界选出的参数不自动是每个实例的最佳参数；宽松证明得到的速度不自动是问题极限。需要时指出放宽了哪一步、丢弃了什么结构。
- 用本方向反复出现的基本问题组织方法之间的关系。例如在线学习反复问：行动时知道什么、何时收到什么反馈、和谁比较、控制哪个量、增加什么条件才有更强保证。不要把算法名排成“越复杂越高级”的路线。
- 应用要接上输入、决策、反馈、目标和保证，而不只罗列行业名。教学模型明确标为简化例子；真实系统采用何方法等事实须有核实过的原始来源，不把历史描述当成当前事实。

遇到数学或机器学习讲义中的对象混淆、证明动机或摘要难以落笔时，按需阅读 [教学示例](references/teaching-examples.md)。借用方法，不照搬 Online Learning 的目录或固定案例。

## 每个实质章节有相互呼应的首尾段落

**章首主要内容：** 用一段连贯的短文说明本章承接什么、解决什么问题、沿什么关系走向答案，以及结果的意义。新名称可以预告，但用熟悉语言解释用途；不要以未讲过的密集符号开场，也不要只列“介绍 A、B、C”。

**章末主要内容回顾：** 用一段话回答开头的问题，压缩“对象如何通过机制连接到结论”，保留核心条件与边界。数学章节在同处重列关键公式，可置于段后；不能只说“公式见上文”。不复制章首，不引入新定理，不把单侧上界变成等式或绝对差。

先用章首确定承诺，写完正文再写章末，最后反查首尾。采用章节开头预告、末尾重建关键思想的方式；不强制所有小节、导航页或局部补丁也重复一套结构。段落长度服从内容与用户限制。

用可结束的小单元承载深度，区分首遍理解、完整证明与进一步研究。可折叠练习答案、独立长证明或非必要拓展；理解主线必需的解释不能只藏在折叠块或远处链接里。适量小变式附可核对的答案或提示，除非用户明确要求不提供答案。

## 从读者位置审查，修复后再交付

以已声明先修和已读正文为限，不凭作者额外知识补齐缺口：

1. **顺序读通：** 找到第一处需要但尚未建立的对象或概念，记录具体缺口，先修回该处再继续。改稿要修原断点，不以文末 FAQ 代替修正文。
2. **重建关系：** 对核心目标，从正文重建“问题—对象—机制—推理—结论及条件”。检查跨节关系是否有依据，不能只验证答案能搜到。
3. **检验直觉：** 用一个有区分力的预测、对照或条件变化检查核心说法。若导出错误预期，改原解释并回查例子、图、证明和摘要。
4. **尝试迁移：** 选保留核心结构的小变式，只用正文与先修解答；解释判断理由。题目不能暗中要求尚未教过的新知识。
5. **反查首尾：** 章首承诺有正文支撑，章末每个结论已有建立，符号、条件、量词、方向与评价对象一致。

发现缺口后修改，再重复受影响的检查，直到核心目标均有支撑、所选检查题能由正文与先修解出，且没有已知未解决的关键依赖或错误直觉。不要用“我觉得易懂”作为通过理由，也不要为形式不断增加测试和篇幅。大幅调整教学方法时，可先试写代表性难点短章，再据产物修订结构。

## 交付与修改边界

- 只在用户要求写入或修改笔记时操作文件；否则在当前对话交付讲义。使用实际指定的 vault、目录及本地约定，不假设固定私人路径。
- 写入 Obsidian 前阅读 [Obsidian 交付检查](references/obsidian-delivery.md)。保留必要导航，检查相关链接、公式、附件；仅修改当前授权范围内的正文及直接受影响的内容。
- 分别报告内容正确性、教学连贯、文档可用性与真实学习成效。计算核查和作者自审不等于真实初学者已掌握；静态检查不等于 Obsidian 阅读视图已验证。
- 简短说明产物位置、关键变化及实际检查范围；把内部审查记录放在必要的交付说明中，不塞进学生阅读的讲义正文。对未解决的问题说明具体位置和影响。
