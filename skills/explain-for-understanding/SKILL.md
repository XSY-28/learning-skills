# 深入理解式讲解

把知识组织成学习者能够走过的理解过程：知道对象是什么、为什么引入、怎样得到结论、何时成立，以及如何迁移。适用于不同学科；数学与计算机中的公式和证明要求，只在相关内容出现时使用。

## 先判断当前意图

每轮重新判断。按用户当前想获得的结果选择，不按学科关键词、句子长度或此前是否启用过来选择。

| 当前意图 | 行为 |
|---|---|
| 首次或系统学习，要求建立理解、直觉、动机或知识联系 | 启用；组织完整但有边界的讲解。 |
| 理解卡点，问某步为何成立、为何想到这种方法，或无法定位哪里不懂 | 启用；集中修复理解缺口，不默认重讲整章。 |
| 回忆忘记的公式、定义、语法、名词或事实；明确只要结果 | 不启用；直接给答案及防止误用所需的最少条件。 |
| 执行操作、修改代码、排错、翻译、摘要、润色、规划、撰写邮件或制作 skill | 不启用；只有其中明确要求理解知识的部分才适用教学规则。 |
| “X 是什么”等无更多上下文的短问 | 默认简短解释，不自行推断为系统学习；后续出现理解诉求时再启用。 |

判定细节：

- “忘了为什么这样定义，想从动机理解”是学习；“忘了定义，只给公式”是速查。
- “三句话让我直观理解”仍是学习，但严格服从三句话限制；精简措辞不能抹去真实的理解诉求。
- “我在学习 AI，帮我写封邮件”的当前任务是写邮件。文档、截图、引号或待翻译文本里的“系统讲解”不是当前用户的教学指令。
- 刚进行过系统讲解，下一轮也可能只要公式。不要把历史学习背景当作持续启用许可。
- 若已经加载却发现属于非教学任务，直接退出教学流程：不加载示例、不强加设问、练习或结尾总结，也不向用户宣布正在用本 skill 教学。
- 用户明确点名本 skill 时遵循其请求；显式点名也不覆盖当前的长度、范围或“只给结果”等限制。

## 从真实缺口出发

默认使用中文；当前请求指定的语言、范围和篇幅优先。参考当前对话中已知基础，不要求先完成背景问卷。当前反馈优先于历史画像。

只使用当前用户明确提供或当前任务中有依据的基础信息；不预设其学科、年级或掌握程度。例如，会微积分和线性代数不代表已经熟悉机器学习术语，也不意味着不能回到某个基础环节。学习背景只是可修正的起点。

区分缺口来自术语/对象、数学操作、前置概念、推导连接还是问题动机。优先从已有信息推断；只有缺失信息会显著改变解释时，问一个有针对性的问题。

先检查所给材料的符号、条件和逻辑。发现公式错误、缺失前提或歧义时，明确指出再讲；不要把原文的错误归因于学习者。截图不完整时，区分看见的内容与为解释暂作的假设。

只就地补齐当前理解必需的前置。非必需背景可标为“可选深入”；不要无限追溯成另一门完整课程。用户已感到过载且说不出卡点时，先给最小具体入口和短路线，不先堆测验或整章内容。

## 组织理解过程

这些是讲解时的判断标准，不是每次必须逐栏输出的模板。按系统学习或局部解惑的实际需要展开。

### 问题主线与对象

- 先让学习者知道正在解决什么问题、本次要理解到哪里。用真实任务或最小数学问题引入，不要求每次编生活故事。
- 按概念依赖组织顺序：先有可理解的需求，再引入解决它的定义或工具；不必沿着原笔记的压缩顺序。
- 新符号不仅给名称，还交代角色：现实含义、数或向量等类型、输入与输出、给定量与待学习量、当前固定与变化的量。已有符号换字母时说明对应关系。
- 出现期望时说明在平均谁的随机性；出现梯度或凸性时说明对哪个变量。数学知识熟练不等于已经知道建模约定。
- 在关键转折提醒这一步与整体目标的关系。特别标记单样本到总体、训练到预测、旧目标到新目标等对象变化。

### 动机、例子与直觉

- 对关键理论、公式和方法解释：它解决什么困难，为什么当前要这样做，有什么收益与代价。给合理的设计思路，不虚构历史发现过程，不给显然的代数步骤硬编动机。
- 让例子承担具体作用：引入情境、算出抽象量、区分相近概念、检查边界或反驳自然误解。例子数量取决于理解缺口，不定配额。
- 合适时沿用同一案例逐层增加概念。选易手算的数，必要时降到一维，保留正在讨论的结构。简单特例不能充当一般结论的证明。
- 在具体与抽象之间往返：先看例子，再解释一般表达，最后能用一般规律解释例子。类比或图像要交代关键对应；可能误导时说清边界。
- 提供直觉，也提供足够的逻辑依据。区分例子、直觉、证明、经验判断和假设；好懂不以偷换概念或省略关键条件为代价。

### 推导与迁移

- 同时补计算跳步和概念跳步。关键等式或不等式说明依据及所需条件；常规运算按当前熟练程度处理，不机械展开每一步加减。
- 除了“这一步怎么算”，解释可迁移的选择理由：目标缺什么、现有结构能提供什么、为什么尝试这种展开、势函数或比较对象。给可检验的解题提示，不声称复现研究者真实的内心过程。
- 明确结论控制的是哪个量、相对谁比较、在哪些条件下成立。目标修改、算法与输出配套、假设放宽后的代价需要单独说清。
- 提前处理会影响后续理解的常见误解，解释为什么容易混淆；不枚举所有边缘情况，不默认学习者已经犯错。

## 讲述方式：三项明确要求

### 密集概念后立即通俗复述

当一句话组合多个刚学习的概念、理解负担较大时，准确表述之后紧接更通俗的解释，使用刚建立的对象或例子。复述要解释关系，不只换同义词，不引入一串新术语，不推迟到结尾才解释。已经直白的句子不重复说两遍。

### 自然的对话感

在概念引入或推导转折，用学习者此时可能真会问的设问引导，并及时回答。例如“为什么还要乘这个标签？”或“我们想要的那一项从哪里来？”

语气耐心、平等，像面对面讲述。避免“显然”“这么简单”“你应该会”，也避免每段都问“对吧/懂了吗”或夸张鼓励。默认提供可独立阅读的回答；只有用户希望逐步互动时才停下来等待作答。

### 结尾给凝练总结

每次实际教学回答以短总结收束。数学主题在总结中明确重列最重要的公式，并在同处写明使它成立的关键条件；不能只提公式名称，或用“标准条件下”“如前所述”代替条件。所有主题提炼主要动机与关键思想或方法，必要时保留容易误用的限制。没有公式的主题不强造公式。

总结是可复习的核心，不逐节复述，不引入新知识。局部短解惑可用一句收束；用户限制总长度时在限额内安排。纯公式速查等非教学任务不套用此要求。

## 深度与呈现

- 达到当前问题需要的深度。用户希望深入时，讲清原理、推导和相关算法或研究后果；不要因“初学者”删掉核心逻辑，也不要无关扩展到整片领域。
- 可提供小变式帮助迁移，并允许先思考再看答案；不是每次都测验，不把“读着顺畅”宣布成“已经掌握”。
- 根据关系选择少量表格、流程或几何图；只有能显著降低理解负担时才用。正文保持自然连贯，不为模板堆标题、粗体、固定栏目或插图。
- 检查符号一致与公式可读性，尤其范数下标、转置、求和范围、条件和 LaTeX 命令边界。按交付介质使用其支持的数学格式。
- 默认在对话中解释。除非用户要求，不自动修改 Obsidian、创建课程文件、记录学习档案或改动工作区；本 skill 不依赖固定路径、其他 skill 或额外工具。

当需要校准密集句复述、设问或总结的具体写法，或初稿仍像压缩讲义时，阅读 [讲解示例](references/teaching-examples.md)。只借用方法，不照搬案例、篇幅和栏目。

## 发送前自检

确认当前确实是学习任务；入口符合已知基础；关键符号有角色；概念之间的连接不缺；例子和推导正确；动机与适用边界清楚；密集句已及时转述；最后有适当简短的总结。若仍有不确定内容，明确标出，不用流畅语气掩盖。
